# TB2 Run 32047133236 Deep Audit

## Verdict

Run `32047133236` is a valid negative outcome witness, not promotion evidence.
It solved 14/20 tasks against 17/20 in the frozen `repair20-v1` baseline. The
same DeepSeek V4 Flash response model was observed in executor and bootstrap
receipts. Serving fingerprint differences are metadata and are not a gate.

The run has five negative flips and two positive flips:

- losses: `extract-elf`, `sanitize-git-repo`, `torch-tensor-parallelism`,
  `video-processing`, `write-compressor`;
- gains: `count-dataset-tokens`, `largest-eigenval`.

The comparison includes the bootstrap call in treatment resources. Across the
common solved cohort, total tokens fell by 7,542,747, but uncached input rose by
347,863 and normalized cost rose by 0.140504157. Five tasks exceeded the
per-task resource guardrail. Outcome and efficiency therefore both fail the
promotion contract.

## Harness defects found

The initial repair implementation was fail-open in several places:

1. The promotion gate compared only the baseline/treatment intersection, so a
   caller could omit a baseline-solved task and obtain a passing verdict.
2. Requested model text was accepted instead of observed executor, bootstrap,
   and canary identity.
3. Baseline provenance checked hash lengths rather than the exact frozen
   artifact hashes.
4. Missing censor state was coerced to `false`.
5. A compiler status label could resolve a pending effect without its provider
   delivery ID, compiler fact/request evidence, state read, or terminal-call
   evidence.
6. Persistent lifecycle booleans were accepted even when every lifecycle count
   was zero.
7. Conflicting duplicate receipts contributed positive counts before the
   report failed.

The repaired contracts freeze exact `repair20-v1` and `full89-v1` task sets,
require typed censoring and observed identity, validate atomic effect evidence,
recompute persistent lifecycle use, and reconcile submit, completion, red-test,
and recap evidence.

## Per-loss trajectory evidence

This analysis uses only the frozen outcome/resource rows, Mini-SWE agent
trajectories, and central receipts. It does not read verifier tests, reference
solutions, reward files, CTRF data, or verifier output.

| task | first action divergence | first GT provider-view change | terminal evidence | attribution |
|---|---:|---:|---|---|
| `extract-elf` | 1 | 1 | `DeadlineReserveReached`; 59 executor calls, five submit holds, no recognized validation action | GT-context causal candidate, not proven |
| `sanitize-git-repo` | 1 | 1 | submitted after 41 executor calls and one workspace-changing action; no recognized validation action | GT-context causal candidate, not proven |
| `torch-tensor-parallelism` | 1 | 12 | submitted after 52 executor calls and nine checks; final reasoning remained uncertain about sharding/input and gradient semantics | model-sampling/implementation divergence preceded GT visibility |
| `video-processing` | 1 | 61 | `StepLimitExceeded` at 100 executor calls; no submit attempt and no recognized validation action | model-sampling/exploration divergence preceded GT visibility |
| `write-compressor` | 1 | 1 | `DeadlineReserveReached` after 12 executor calls; completion predicates existed but no certificate was established | GT-context causal candidate, not proven |

For `torch-tensor-parallelism` and `video-processing`, the treatment action
trajectory diverged at action one while the provider view remained identical
to the pre-GT control until calls 12 and 61 respectively. GT therefore did not
cause their initial divergence. For the other three losses, the first GT view
change and first action divergence coincide. That is temporal eligibility for
causation, not proof of causation; the model sampled a different trajectory at
temperature 1.0, and no evidence currently isolates which added fact changed
the decision.
