## Closed implementation defects

1. Graph identity survives publication. Every available index receipt carries
   the SQLite, manifest, and indexer SHA-256 values plus source revision, schema,
   coverage, and parser-failure evidence. Boolean-only readiness is rejected.
2. Source deletion and source-to-non-source transitions consult the exact prior
   mirror when bounded sensor text is absent. Large extensionless sources cannot
   leave stale graph nodes.
3. Selected contributions require provider-value certificates. The release gate
   independently reconstructs all 14 per-call requirements from provider,
   compiler, graph, state, action, semantic, and replay receipts; an embedded
   `PASS` cannot authorize itself.
4. Assistant messages are canonically hashed before and after compaction. Equal
   character counts are insufficient; content, reasoning, metadata, or order
   changes fail release.
5. Provider exposure requires a received response. Provider errors count as
   attempted transport, never confirmed exposure or delivery.
6. Completion proves the exact executable predicate set with unique IDs,
   commands, current revisions, and 64-hex observation hashes. Unrelated or
   self-authored observations cannot satisfy completion.
7. Timeout/censor classification is stage-aware. Task and verifier failures are
   not excluded as provider censors based on generic names or message text.
8. Instruction-owned external deliverables remain in workspace-impact sensing;
   unrelated external paths can still abstain without costly rescans.
9. Convergence returns only proven evidence-boundary violations. Generic stall
   and budget risk stay private. Relative paths, variables, interpreter strings,
   and command substitutions cannot hide grader-only targets.
10. Process composition is anchor-centered, bidirectional,
    uncertainty-preserving, and globally expansion-bounded.
11. Dense release identity requires the exact Snowflake revision, ONNX hash,
    tokenizer hash, CLS pooling, L2 normalization, and 512-token limit.
12. DeepSWE merge independently rebuilds replay, trajectory, and intervention
    integrity and requires exact response model and provider identities.
13. Current treatment workflows invoke a manifest-backed release guard. The
    manifest remains `benchmark_authorized: false` until exact-commit proof.
